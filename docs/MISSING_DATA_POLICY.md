# 欠損ポリシー (確定) — MAIBuilder 設計書 §4/§9 への差分

作成: 2026-07-26 / 実装: `builder/normalize.py` (単一実装、全経路が共有)

## なぜ明文化が必要か

生 JV-Data のカバー範囲は **2025 年以降**。コーナー系5項目と賞金は raw から復元しているため、
**直近N走が 2024 年に食い込む馬では部分欠損する**。STEP2 は「直近N走の平均」なので、
これは長期バックテストだけの問題ではなく **10月デモの当日予想でも普通に発生する**。

方針が曖昧なままだと、値を持つ 2 頭だけで計算した無意味な z-score が印を動かしてしまう。

## 決定した方針

### 1. 列のレース内カバレッジゲート

ある列が使われるのは、そのレースで **値を持つ馬が `MIN_HORSES`(=4) 頭以上 かつ
出走頭数の `MIN_FRACTION`(=50%) 以上** のときのみ。満たさない列は
**そのレースでは誰の寄与にもしない** (`decision="skipped_low_coverage"` として記録)。

理由: 2 頭だけの平均・標準偏差から作った z は統計的に無意味で、その 2 頭が印を独占する。

分散ゼロの列も不使用 (`decision="skipped_no_variance"`)。

### 2. 使用する列で値が無い馬 → 寄与 0 (中立)

寄与分解には `available=false, contribution=0.0` として **明示的に記録**する。

**再正規化 (持っている列だけで割り増す) は採用しない。** 実績の薄い馬のわずかな情報が
増幅され、データが少ない馬が静かに有利になるため。「その馬について分かっているのは1項目だけ
なので平均付近に置く」が誠実な扱い。

### 3. カバレッジを返して UI で見せる

`score_race_detailed()` は馬ごとに `{"n_used": 使用列数, "n_with_value": 値があった列数}` を返す。
UI 側で「この馬はコーナーデータが2走分のみ」のように表示し、**欠損を隠さず誠実さに変える**。

集計の元になった過去走数も表示できるよう、寄与分解には列ごとの `available` を含める。

## 実装と適用範囲

`builder/normalize.py` の `race_z()` / `column_decision()` が単一の実装。以下すべてが共有する:

| 経路 | 用途 |
|---|---|
| `model.score_race_detailed()` | 印の生成・寄与分解 (API `/api/predict`) |
| `matrix.prepare_races()` | 研究用の事前正規化 (純Python) |
| `vsearch.prepare_numpy()` | 研究用の事前正規化 (numpy・ベクトル化) |

3 経路の一致は既存のパリティテスト
(`test_prepared_matches_direct_evaluation`, `test_numpy_matches_pure`) が担保する。

## 既存証跡への注記

Phase 3b / 3c の探索結果 (`docs/evidence/2026072*`) は **本ポリシー導入前** に実行されており、
当時の閾値は「値が 2 頭以上」だった。本ポリシーは低カバレッジ列を除外する方向の変更なので、
「OOS エッジ無し」という当時の結論を覆すものではない (エッジを作る変更ではない)。
