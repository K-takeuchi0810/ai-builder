# MAIBuilder の使い方

設計書: `MAIBUILDER_DESIGN_v0.3.md` / 判断の根拠: `evidence/20260726_FINDINGS_preset_weights.md`

前提: `keiba-yosou` が兄弟ディレクトリにあり、`keiba.db` が最新であること。
このツールは **keiba.db を読むだけ** で、書き込みは一切しません。

## 0. 最初に: `python` ではなく `.bat` を使う

**システムの `python` では動きません。** 32bit で numpy が入っておらず、
`ModuleNotFoundError: No module named 'numpy'` になります。仮に入れても
425列 × 6年の行列 (約5GB) は 32bit では扱えません。

使うのは `keiba-yosou` の 64bit venv (Python 3.14 / numpy 2.4) です。
毎回パスを打たずに済むよう、リポジトリ直下にランチャーを置いてあります。

| コマンド | 中身 |
|---|---|
| `build_daily.bat` | 当日の基底列を構築 |
| `serve.bat` | サーバを起動 |

別の Python を使いたい場合は環境変数で上書きできます。

```
set MAIB_PYTHON=C:\path\to\python.exe
```

自分で直接叩く場合はこちら (どちらも同じ):

```
..\keiba-yosou\.venv64\Scripts\python.exe scripts_build_daily.py
..\keiba-yosou\.venv64\Scripts\python.exe -m builder.api
```

## 1. 当日朝: 基底列を作る (唯一の準備作業)

```
build_daily.bat
```

実測で **36レースで約5分**。発走直前に始めると待たされるので朝に済ませます。
すでに作ってあれば即座に状態だけ表示します。

出力例:

```
完了 レース数=36 281s mem=2.1GB peak=3.4GB
  予想できるレース: 36/36
  馬体重が発表済み: 0/36 (未発表は発走約50分前に発表され、UI が自動で印を更新します)
  項目の利用率: 中央値 75.8% 最小 2.6% 最大 99.5%
  開催: 札幌 12R / 新潟 12R / 中京 12R
```

- `--date 20260802` で日付を指定 (既定は今日)
- `--rebuild` で作り直す (レース確定後に結果を取り込みたいとき)
- 当日行列の形が変わったとき (`DAILY_VERSION` の更新時) は自動で作り直しになる
  — キャッシュ名にバージョンが入っているので、古い形を掴む事故は起きない
- `--require-confirmed` は過去日で試すとき (確定済みレースのみ)

アプリと一緒に落ちないよう、独立プロセスでの起動を推奨します
(`LONG_RUNNING_JOBS.md`)。原子的書き込みなので途中で落ちてもキャッシュは壊れません。

```powershell
Start-Process -FilePath "C:\Users\kizun\dev\ai-builder\build_daily.bat" `
  -WorkingDirectory "C:\Users\kizun\dev\ai-builder" `
  -RedirectStandardOutput "out\logs\build_daily.log" `
  -RedirectStandardError "out\logs\build_daily.log.err" -WindowStyle Hidden
```

## 2. サーバを起動する

```
serve.bat
```

引数なしで動きます (日付は今日、バックテスト期間も既定が入ります)。
朝の準備が済んでいれば数秒で立ち上がります。
`http://127.0.0.1:8780/` をブラウザで開きます (スマホ幅で作ってあります)。

止めるときは `Ctrl+C`。

### 開催が無い日に画面を確認する (検証モード)

JRA は平日に開催がないので、平日に `serve.bat` を起動すると**レース0件**になります
(これは異常ではありません)。過去の開催日を指定しても、確定済みなので全レースが
「終了」になり、**印の画面は確認できません**。

そのための検証モードがあります。

```
serve.bat --date 20260726 --preview
```

確定済みのレースを「発走前」として表示するので、印・寄与分解・凡例をすべて
確認できます。印は PIT を守って対象レースより前の過去走だけから作られているので、
**発走前に出したはずの印そのもの**です。ただし結果を知った状態で見ることになるため、
画面上部に赤いバナーが常時出ます。

> 検証モード: 確定済みのレースを発走前として表示しています(結果は既に出ています)

起動時に構築済みの日付が分からなくなったら、ログが教えてくれます
(レース0件のときに「構築済みの日付」と推奨コマンドを表示します)。

| 引数 | 用途 |
|---|---|
| `--date` | 対象日 (既定: 今日) |
| `--preview` | 確定済みレースを発走前として表示する (上記) |
| `--build` | 当日行列が無ければ起動時に構築する (朝の準備を省いた場合。5分待つ) |
| `--no-backtest` | バックテスト用行列を読まない (起動が最速。成績カードは出ない) |
| `--backtest-from` / `--to` | 成績カードの期間 (既定: 表示期間の開始〜当日) |
| `--port` | 既定 8780 |
| `--weights` | 重みファイルを差し替える (通常は指定不要) |
| `--require-confirmed` | 過去日で試すとき |
| `--host 0.0.0.0` | 同一LANの他端末から開けるようにする(下記の注意を読んでください) |

### 複数人で見る場合

`serve.bat --host 0.0.0.0` で同じネットワークの端末から開けます。マイAIを人ごとに
作れば、成績比較と回収率ランキングがそのまま人ごとの比較になります。

**認証はありません。** 同じネットワークにいる誰でも開けて、誰のマイAIでも編集・削除
できます。信頼できるネットワークだけで使ってください(既定は `127.0.0.1` で、
この端末からしか開けません)。

起動ログで **プリセット重みが `per_column_univariate`** であることを確認してください。
別の方式やファイルが読まれていれば、それが表示されます。

## 3. 画面の流れ

**① レース** — 競馬場ごとにまとめて一覧。状態がチップで出ます。

| チップ | 意味 |
|---|---|
| 予想できます | そのまま押せます |
| 一部の項目が使えません | 選んだ項目の一部がこのレースで使えない状態 (印は出ます) |
| 馬体重の発表待ち | 発走約50分前の発表後、**画面を開いたまま自動で印が更新**されます |
| 終了 | 発走済み。開くと印の代わりに着順が出ます (印は発走前のレース専用) |

会場が複数ある日は、一覧上部の**会場チップ**でその会場へ飛べます。
一覧を開くと現在時刻に最も近い未発走レースが視界に入るようスクロールします。

**② マイAI** — 重視する項目を選びます。所要2〜3分。

- **重視する項目**: 単項目28件 (斤量・騎手・枠位置など)。**「人気(市場)」は選べません** (後述)。
  ここはあらかじめ集計方法が決まっています (例:「直近3走の平均着順」は直近3走に固定)
- **詳細設定** (初期は閉じています): 集計対象9件について、**どの条件のレースを・どこまで
  さかのぼって**集計するかを自分で決められます。項目をONにすると「全レース × 直近3レース」が
  既定で入り、条件チップとスライダーで変えられます。生成される組み合わせの数は
  「この項目で◯通りの組み合わせを使います」と各項目に出ます
- 保存すると「これまでの成績」が出ます。1番人気AIと**同じ大きさで並べて**表示され、差が
  `±◯pt` で付きます (どちらが良いかが色と符号で分かる)

**③ 予想** — 印 (◎○▲△×) と自信度。**馬の行をタップすると「なぜこの印か」が開きます。**

自信度は通常は緑、**選んだ項目の半分以上がそのレースで使えなかったときは1段下げて黄色**で出し、
理由の一文を添えます (黄色は「注意・保留」専用の色にしてあります)。
オッズは30秒ごとに取り直し、ヘッダの「更新」ボタンで手動でも取り直せます。

寄与は「その馬の評価を動かした量のうち各項目が占める割合」です。
生の数値ではなく割合なのは、項目ごとに桁が100倍違い小数1桁では全部 0.0 になるためです。

**④ 成績** — 当日確定分のマイAI同士の比較。①◎的中**率** → ②出し抜き数 → ③◎複勝率 の順。
レースごとに適用AIを切り替えられるため AI ごとに母数が違います。的中数を第1キーに
すると多く使ったAIが機械的に上位になるので、率で並べて数を併記しています。
1番人気AIは基準行として順位を付けずに併記されます。

同じ画面の下に**回収率ランキング**があります。当日36レースでは統計的に判断できないので、
**表示期間の全レース(数千件)**で集計しています。信頼区間が重なる相手は同順位にし、
どれも差が誤差の範囲なら「順位は付けられません」と出ます。

実測ではどのマイAIも 68〜75%、基準の1番人気AIが 77% です(単勝の控除率は20%なので
長期の上限は約80%)。回収率で市場を上回る設定は見つかっていません。

**買い目** — 予想画面の下で**自分で組めます**。金額は扱いません。

操作は3段です。

1. **使う馬** — 全出走馬から選びます。印は表示されたままなので、印を参考にしつつ
   **印が付いていない馬も入れられます**(印は分析の可視化で、推奨ではありません)
2. **軸** — 使う馬の中から1〜2頭。流す買い方で中心にする馬です
3. **券種と組み方** — 券種ごとに ON/OFF と組み方を選びます

| 券種 | 選べる組み方 |
|---|---|
| 単勝・複勝 | 軸の馬だけ / 選んだ馬すべて |
| 馬連・ワイド | 軸1頭から流す / ボックス |
| 馬単 | 軸を1着に固定 / 軸を2着に固定 / 両方 / ボックス |
| 三連複 | 軸1頭から流す / 軸2頭から流す / ボックス |

既定は「◎を軸、○▲△×を相手」なので、**触らなければ印どおりの買い目**が出ます。
「印どおりに戻す」でいつでも戻せます。点数は券種ごとと合計の両方に出ます
(ボックスは頭数が増えると急に増えます)。

どの買い方が有利かは表示しません。**実測でエッジは見つかっていないので、
示せる根拠がありません**(§4)。

組み方と軸の頭数が合わないとき(例: 軸2頭で「軸1頭から流す」)は、**その券種だけ**
理由を出して他の券種は作ります。全部消えると何が起きたのか分からないためです。
出走していない馬番は組みません。

買い目の下に**「公式サイトへの入れ方と読み合わせ」**があります。公式のSTEP順
(レース → 式別 → 馬番 → 金額) に並べ替えた案内と、入れ終わったあとに突き合わせる
表が出ます。**入力後に必ず読み合わせてください** — 公式の確認画面を見ながら、
式別・馬番・点数・レースが一致しているかを確認します。

馬単のように順序が決まっている券種は `11→10` と矢印で出ます。馬連の `11-10` とは
別の馬券なので、矢印の向きをそのまま入れてください。

**QRコードはこのツールでは作れません。** スマッピー投票のQRデータ形式は非公開です
(公式サイトが配信しているスクリプトを全文調べても生成コードは入っていません = サーバ生成)。
外部サイトから買い目を渡す口も無く、公式サイト自体が**金曜18:30〜日曜最終レース締切**しか
稼働しません。形式を推測して作ると読めないか、**間違った馬券を実際のお金で登録する**
危険があるため実装していません。

公式に作らせる自動入力の実装計画は `SMAPPY_QR_PLAN.md` にあります
(公式サイトの稼働時間中に実物を観測してから作る方針)。

## 4. 知っておくべきこと

**このツールは回収率商品ではありません。** 35,036 + 119,069 + 63,525 候補を探索して、
単勝市場を上回る out-of-sample エッジは見つかりませんでした。的中率でも1番人気に
勝てません (約20% vs 33%)。印と寄与分解は**分析の可視化**であり、賭け金の判断根拠に
しないこと — 納得感のある説明は主観的確信を強めますが、エッジの不在とは無関係です。

**「人気(市場)」は選べません。** 含めると ◎ の95.9%が1番人気と一致し、他の項目を
足しても ◎ が変わるのは0.2〜2.2%だけになり、「選んだ項目が根拠になる」という
作りが成立しませんでした。市場人気は基準の「1番人気AI」専用です。

**「◎が1番人気と一致」の目安は 30〜60%** (実測44%)。低いほど良い数字ではありません。
0%近辺は市場と系統的に逆を向いている異常、90%台なら市場人気がスコアを支配している疑いです。

**コーナー通過順・獲得本賞金は学習サンプルが薄い** (中央値53レース / 143レース)。
生JV-Dataの保存範囲が2025年以降しかないためで、選ぶと画面に
「この項目は過去◯◯レース分の学習です」と出ます。使うかは自分で判断してください。

## 5. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| `ModuleNotFoundError: No module named 'numpy'` | システムの `python` を使っている。`build_daily.bat` / `serve.bat` を使う (§0) |
| 「きょうのレースがまだ準備できていません」 | その日の行列が未構築。`build_daily.bat --date ...` |
| 「予想に使える項目が選ばれていません」 | 項目未選択。人気だけを選んだ旧設定もここに落ちる |
| 「更新できていません」のチップ | サーバが落ちている。表示は最後に取得できた内容 |
| 自信度が「—」 | 重みファイルの閾値が旧形式。`scripts_recompute_thresholds.py` |
| 「プリセット重みの列構成が一致しません」 | 別の列構成で学習した重み。起動ログのパスを確認 |
| 印が出ない | 上の警告カードが理由を書いています (重み無し / 全項目がゲート落ち等) |

## 6. 補足: 別系統のツール

`python -m builder.server` は**製品ピボット前の探索用サーバ**で、参加者向けUIとは
別物です (既定ポート8770)。条件別の成績を眺める調査用なので、通常は使いません。
