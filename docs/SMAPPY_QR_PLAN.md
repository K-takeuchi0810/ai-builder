## 1. 調査で確定したこと (2026-07-28)

| # | 事実 | 根拠 |
|---|---|---|
| 1 | **QR の payload はサーバ生成。クライアントJSに無い** | `qrcode.jra.go.jp` の自前スクリプトは `tmpl/jqm.extend_qr_180907.js` (15,450バイト) のみ。全文取得して `qrcode` `QRCode` `encode` `toDataURL` `canvas` `base64` `Reed` `polynomial` を検索し **ヒット0**。中身は jQuery Mobile の UI 拡張 |
| 2 | **稼働時間は金18:30〜日曜最終レース締切** | サイト本文「誠に申し訳ありませんが、ただいまの時間帯は投票用QRの作成ができません。（作成可能時間）原則、金曜日18時30分～日曜最終レース締切まで」 |
| 3 | **外部サイトからの受け渡し口は無い** | 公式手順は STEP1〜STEP9 の画面操作のみ。URLパラメータ・API の記述なし (`jra.go.jp/kouza/qrbet/howto_odds.html`) |
| 4 | **QR 作成には賭け金入力が必須** (100円単位) | 同ページ STEP6 |
| 5 | 形式自体は実装可能 (JRA-VAN アプリが 2018-10-03 に QR 作成機能を搭載) だが **公開仕様は無い** | JRAシステムサービス プレスリリース |

### ここから出る結論

**MAIBuilder が独自に QR を作ってはならない。** 形式を推測して作れば、読めないか
**違う馬券が実際のお金で登録される**。唯一の正しい経路は「公式に作らせる」:

```
MAIBuilder(買い目) → 公式サイトのフォームへ自動入力 → QR は JRA が生成
```

参考にした動画のタイトルが「スマッピーQR作成**自動操作**」なのも、形式解析ではなく
公式サイトの操作自動化だから。

## 2. 金曜の観測チェックリスト

窓は金18:30〜日曜まで。**逃すと1週間待ち**なので一度で取り切る。
記録先: `docs/evidence/YYYYMMDD_FINDINGS_smappy_dom.md`

### 2.1 画面ごとに取るもの

各 STEP で以下を必ず保存する。

- [ ] URL（クエリ・ハッシュを含む完全な形）
- [ ] `document.forms` の name / action / method / 全 element の tag·type·name·id
- [ ] 操作対象要素のセレクタ（id 優先、無ければ安定した属性の組み合わせ）
- [ ] 1操作あたりのイベント種別（`click` で足りるか、`change`/`input` が必要か）
- [ ] 画面遷移がページ遷移か jQuery Mobile のページ内切替か

### 2.2 STEP ごとの具体項目

| STEP | 取るもの |
|---|---|
| 開催・レース選択 | 競馬場コードとレース番号の指定方法。`select` か リンクか |
| 式別選択 | 単勝/複勝/馬連/ワイド/馬単/三連複 の値。**内部コードを記録**（表示名ではなく value） |
| 馬番選択 | チェックボックス格子か。◎を軸にする「流し」の入力方法があるか。1着/2着の列が分かれているか |
| 点数・組み合わせ | こちらが組んだ組を1点ずつ入れるのか、軸+相手で入れるのか |
| 金額 | 必須か。単位。**触らないので位置の確認のみ** |
| 確認画面 | 入力内容の読み出し方（読み合わせに使う） |
| QR 画面 | `<img>` の src が data URI かサーバURL か |

### 2.3 実装可否を決める項目

- [ ] **URL に状態が乗るか**（乗るなら自動操作より安全なディープリンクが可能）
- [ ] **一括入力欄があるか**（テキスト貼り付けで複数点を入れられるか）
- [ ] CSRF トークン・セッションの有無（自動入力がトークンを壊さないか）
- [ ] 1つの QR に複数レースを入れられるか（「オッズ選レース」では当該レースのみ追加可という記述あり）
- [ ] 自動化を禁じる記述が **利用規約** にあるか ← **これを最初に読む**。禁止なら自動入力は作らず、§4 に切り替える

## 3. 実装方式（観測後に確定）

外部依存ゼロの制約があるので、第一候補は**ブックマークレット**。

```
MAIBuilder: 買い目 → クリップボードに JSON + ドライバを1タップでコピー
ユーザー:   公式サイトを開く → ブックマークレット実行 → 馬番と式別が自動で入る
ユーザー:   金額を入力 → 確認 → QR 作成（ここは人がやる）
```

### 安全弁（実装時に必ず入れる）

1. **構造の指紋照合**: 観測時に記録した要素構成と一致しなければ**何もせず停止**して理由を出す。
   ページ改修に黙って追従して誤クリックするのを防ぐ
2. **金額欄に触らない**
3. **最終の確定/QR作成ボタンを押さない** — 点検の機会を必ず人に残す
4. **`qrcode.jra.go.jp` 以外では動かない**（origin 判定）
5. **入力後に読み合わせを表示**: 式別・馬番・点数を公式画面から読み直して、MAIBuilder 側の
   買い目と**一致しなければ警告**。一致確認は「入れた値」ではなく「画面から読み直した値」で行う
6. セレクタは**1つのテーブルに集約**する（改修時に1箇所直せば済むように）

## 4. 自動化が使えない場合の代替

利用規約で自動操作が禁止されていた場合、または DOM が自動入力に耐えない場合。

- 公式の STEP 順に並べ替えた入力ガイド（レース → 式別 → 馬番 → 点数）
- 入力後の読み合わせ表（券種ごとの点数と馬番を人が突き合わせる）

**これは自動化が入っても残す。** 誤登録の最後の防波堤なので、自動入力の有無に関わらず必要。

## 5. スコープに関する未決事項

**QR 作成には金額が必須**（§1 の4）。現在の設計は「買い目に金額を含めない」なので、
自動入力を金額の直前で止めても、**ツールが金額入力の直前まで案内する**ことになる。

- 金額をツールで扱うか（扱うなら設計書 §1 の DON'T を改訂する必要がある）
- 扱わない場合、金額はユーザーが公式画面で入力する（現行方針の維持）

**現行方針の維持で進める。** 変更が必要ならその時点で相談する。
