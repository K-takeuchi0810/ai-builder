# JRAスマッピーQR連携 — 実装・検証記録

## 結論（2026-07-31）

MAIBuilderで選択した買い目と1点あたりの金額をJRA公式スマッピーへ送信し、
**JRAサーバが生成した投票用データ**からQRコードを表示できる。

MAIBuilderが投票用データを推測して独自生成する方式ではない。公式画面と同じ入力レコードを
`qrcode.jra.go.jp` へ送り、JRAが応答した買い目と送信内容が完全一致した場合だけQRを表示する。

## 実装経路

```text
MAIBuilder（金額・買い目）
  → BOX／ながし／フォーメーションを1点ずつへ展開
  → JRA公式スマッピーのセッションと動的トークンを取得
  → 公式入力レコードを pw_983_i.cgi へ送信
  → JRA応答の買い目を送信内容と照合
  → JRAが返した投票用データをQR画像として表示
```

- UI: `web/app.js`
- API: `POST /api/smappy/qr`
- 公式サイト連携・照合・QR描画: `builder/smappy.py`
- 買い目展開と金額検証: `builder/betslip.py`

## 制約と安全条件

- 金額は1点あたり100円から999,900円まで、100円単位
- 1つのQRは最大50点、合計100万円以下
- 1レース単位で生成
- 出走していない馬番、存在しない枠、成立しない買い目は送信しない
- 1件でも不正な指定があれば部分送信せず、QRを作らない
- JRAが返した全レコードが送信内容と完全一致しない場合はQRを表示しない
- 対象レースが発売対象外、公式サイトの時間外、通信不能、公式画面変更の場合は理由を表示する
- QR作成は購入ではない。競馬場・ウインズの発売機で内容を確認し、利用者が購入操作する

## 実通信で確認した内容

2026-07-31にJRA公式サイトの稼働時間内で、2026-08-01 新潟1Rの
「単勝 1番・100円」をテストデータとして送信した。

- 公式サイトが買い目を受理し、送信レコードをそのまま応答した
- JRA生成の投票用データを受信した
- 公式JavaScriptと同じQRバージョン・誤り訂正レベルでPNGを生成できた
- 購入操作は行っていない

自動テストでは符号化既知値、8券種の形式、50点上限、100円単位、応答照合、
APIでの買い目展開、部分送信防止を固定している。

## 運用上の注意

JRAスマッピーには公開APIがなく、公式Web画面の動的トークンとCookieを利用している。
公式画面の構造が変わった場合は推測で継続せず、`official_page_changed` 等で停止する。
実際の発売機では、QR読取り後に表示されるレース・式別・組番・金額・合計を必ず確認する。
