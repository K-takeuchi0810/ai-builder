## 2. コントラストの実測 (D-2)

計算式は WCAG 2.1 の相対輝度。白地 (`--card`) と `--paper` の両方で測った。

| 変数 | 旧 | 白地 | paper | 新 | 白地 | paper |
|---|---|---|---|---|---|---|
| `--ink-faint` | #8B9486 | **3.14** | **2.89** | #66705C | 5.20 | 4.78 |
| `--minus` | #7C8AA0 | **3.50** | **3.22** | #5D6C82 | 5.34 | 4.91 |
| 文字用 gold | #A8811C | **3.61** (gold-soft 上 **3.09**) | — | #7A5D0F (`--gold-text`) | 6.18 | gold-soft 上 5.28 |

- `--ink-faint` は **25箇所**で最小サイズ本文と組み合わされていた。個別置換では漏れるので
  **色そのものを AA まで暗くした**。`--ink-soft` (5.93) との階層は保持。
- `--minus` はレビュー指摘外だが、**基準との差 (−14pt) は判断材料**なので同じ基準で直した。
- `--gold` は背景・枠線用として据え置き、文字には `--gold-text` を使う。
- `.mark.hon` (◎) のみ `--gold` のまま: 1.55rem (24.8px) で **AA 大文字の閾値 (24px) を超える**ため
  3:1 で足りる (実測 3.61)。かつ ◎ の字形自体が意味を担う。

`tests/test_web_ui.py` にパレットのコントラストを計算するテストを4件追加。
**`--ink-faint` を旧値 #8B9486 に戻すと3件が落ちることを確認済み。**

## 3. 自信度と警告の色分離 (B-2)

実機の `getComputedStyle` 実測:

| 状態 | 背景 | 文字 |
|---|---|---|
| 通常 (`.badge-conf`) | `rgb(226,237,229)` = turf-100 | `rgb(20,97,74)` = turf-700 |
| 降格 (`.badge-conf.low`) | `rgb(246,237,210)` = gold-soft | `rgb(122,93,15)` = gold-text |
| 警告カード (`.warn-card .m`) | — | `rgb(122,93,15)` = gold-text |

これで **gold は「注意・保留」専用**になり、良い知らせ (自信度) と衝突しない。

> 計測時の注意: `getComputedStyle` はライブオブジェクトを返す。最初は
> `low = getComputedStyle(b)` → `classList.remove('low')` → `base = getComputedStyle(b)` と
> していたため両者が同一値になり、「.low が効いていない」と誤読した。値をコピーして再計測。

## 6. C-2 チップ数の削減と直積の可視化

| | 修正前 | 修正後 |
|---|---|---|
| 期間の選択肢 | 9項目 × 11チップ = **99個** | スライダー9本 + トグル18個 = **27個** |
| 一致条件 | 36個 | 36個 (変更なし) |
| 合計 | **135個** | **63個** |

生成される組数の表示 (実機):

- 各項目 (開いている時): `この項目で4通りの組み合わせを使います`
- 各項目 (畳んでいる時): `全レース ほか1 × これまでの全走 ほか1 · 4通り`
- 詳細設定の見出し: `1項目 · 4通り`
- 保存ボタン下: `4項目を選択中(詳細設定で4通りの組み合わせ)`

### 期間の複数選択は削っていない

スライダーは「直近N走」を1つに確定させるが、内部の `lookbacks` は Set のまま。
複数の「直近N走」を持つ保存済み設定を読み込んだ場合、**黙って1つに丸めず**
`この設定は期間を3種類使っています(直近3レース・直近5レース・直近8レース)。スライダーを動かすと1つにまとまります。`
と表示して保持する。現在の保存済み設定 (`out/cache/configs.json`) に複数期間のものは無いことを確認済み。

### 実装上の判断: checkbox ではなく button チップ

`<label>` で checkbox を包む形で作ったところ、実機でプログラム的な `click()` が label に
転送されて**二重トグル**になり、状態が元に戻る事象が出た (`change` は1回しか観測されないのに
`sel.step2` が変わらない)。一致条件と同じ **button + `aria-pressed`** に統一し、
状態の正本を `sel.step2` に置いて DOM の `checked` に依存しないようにした。

実機で全遷移を確認:

| 操作 | lookbacks | 表示 |
|---|---|---|
| 項目ON | `{3}` | 直近3レース · 1通り |
| スライダー→7 | `{7}` | 直近7レース · 1通り |
| 全走も使う | `{7, 全走}` | 2通り |
| 一致条件+1 | `{7, 全走}` | 4通り |
| 区切るをOFF | `{全走}` | 2通り |
| 全走もOFF | `{全走}` (**拒否**) | 2通り + トースト「期間はどちらか一方は必要です」 |

## 12. 全体実行でのみ落ちたテスト (テスト間の状態漏れ)

追加した `test_low_sample_mark_is_not_interactive` は **単独では通り、全体実行では落ちた**。

原因は前回と同じ経路: `api.feature_catalog()` は `api._STATE["preset"]` を読み、
「データ少なめ」は preset の `low_sample_columns` から付く。`tests/test_api.py` に
`api._STATE["preset"] = PRESET` の **直代入が4箇所** 残っていて、合成プリセット
(低サンプル列を持たない) が後続ファイルに漏れていた。

両方向で直した:

1. このテスト自体を ambient state に依存させない — カタログに低サンプル項目を明示的に作る
2. 漏れ元の4箇所を `monkeypatch.setitem` / `monkeypatch.delitem` に変換

確認: `pytest tests/test_api.py tests/test_dom_structure.py` (漏れ元を先に走らせる順序) で 87 passed。
