# 証跡: 10月デモの実現可能性 — 直近レースでのゲート通過率 (2026-07-26)

設計書 v0.3 §4.3 の懸念「生 JV-Data が 2025-2026 のみなので、コーナー系・賞金系は
**当日予想でも部分欠損する**」が、実際にデモを成立させられる水準かを実測した。

## 検証対象

**2026-07-19**(直近開催日 = 10月デモに最も近い条件)、36レース、**425 基底列**
(STEP1 29 + STEP2 396) を `matrix_daily.build_daily()` で構築 (98秒)。

## 結果: 復元データは直近レースで実際に埋まる ✅

| 項目 | 結果 |
|---|---|
| コーナー系列の通過 | **222 / 222 列**が1レース以上で通過 |
| 賞金系列の通過 | **44 / 44 列**が1レース以上で通過 |
| ゲート未通過列 (レースあたり) | **中央値 5 / 425**(最小 0、最大 414) |

→ 生ファイルが 2025-2026 しか無くても、**直近レースの出走馬は直近走が 2025-2026 に入るため
コーナー・賞金が埋まる**。設計の前提は成立している。

比較: **2025-01-05** の同じ構成では未通過列が 304〜413 と大量だった
(過去走が 2024 年以前で復元データが無い)。→ **長期バックテストでは疎、当日予想では密**
という設計書の記述が実測で裏付けられた。

## 「最大 414 列未通過」のレースについて

1 レースだけ極端に欠けるものがある。過去走を持たない馬が多いレース (新馬戦など) で、
集計特徴が原理的に計算できないケース。`/api/predict` が
`all_columns_gated_out` として警告するので、参加者に無意味な印を出すことはない。

## `ready` 判定の修正

当初 `ready = 全列がゲート通過` と実装していたが、この定義では **2/36 レースしか
ready にならなかった**。中央値 5 列欠けただけで「使えない」とするのは誤りで、
デモ進行を不必要に止めてしまう。

修正後:

- `ready` = 出走馬がいて **1 列以上が通過**(= 予想が成立する)
- あわせて `n_columns` / `n_gate_passed` / `gate_pass_rate` を返す
- **参加者が選んだ列が使えるかは per-config で `/api/predict` が警告**する
  (`no_preset_weights` / `all_columns_gated_out`)

一般的な健全性は `today_status`(通過率)で見て、設定固有の可否は予想時に判定する分担。

## 進行台本への含意

- 当日朝のバッチで `gate_pass_rate` を確認する。中央値 0.98 程度が正常。
- 通過率が極端に低いレース (新馬戦など) は座興の対象から外す。
- 参加者が賞金・コーナー系だけを選んだ設定は、そのレースで使えない可能性がある。
  `/api/predict` の警告を UI が拾って「別の項目も選んでください」と促す。
