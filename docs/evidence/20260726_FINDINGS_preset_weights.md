## 3. 自信度ラベルは尺度不変な差に作り直した

旧実装は「1位と2位の生のスコア差」の分位点。生の差は選んだ項目数と重みの
大きさに比例するので、425列で決めた閾値は少数選択に当てられない。
2026年600レースでの実測:

| 閾値の出どころ | 適用先 | 鉄板級 / 有力 / 混戦 |
|---|---|---|
| 同時・旧(生の差) | 425列 | 35% / 27% / 38% |
| 同時・旧(生の差) | 4項目 | 4% / 42% / 54% |
| 同時・旧(生の差) | 3項目(人気なし) | **0% / 0% / 100%** |
| 列別・旧(生の差) | 4項目 | **0% / 0% / 100%** |

`presets.normalized_gap` = (1位-2位) ÷ レース内スコアの標準偏差。
全重みを定数倍しても値が変わらないので、同じ閾値をどの項目数でも使える。

差し替え後 (`scripts_recompute_thresholds.py`、2026年800レースで確認。
証跡: `20260726_confidence_rescale.json`):

| 適用先 | 同時 (閾値 0.370/0.207) | 列別 (閾値 0.468/0.182) |
|---|---|---|
| 425項目すべて | 38% / 26% / 37% | 46% / 29% / 24% |
| 4項目 (人気+集計3) | 8% / 70% / 22% | **19% / 45% / 37%** |
| 3項目 (人気なし) | 19% / 21% / 60% | **22% / 33% / 45%** |
| 1項目 (タイム指数) | 38% / 12% / 50% | 33% / 19% / 48% |

100% 混戦は解消。**列別学習の方がどの設定でも分布が均等**で、自信度ラベルが
情報を持つ (判断B の材料をもう一つ追加)。

**古い形式の閾値は解釈を拒否する** (`scale` キーが無ければ `—` を返す)。
尺度の違う値を突き合わせて「混戦」に張り付いた自信度を見せる事故を防ぐ。

## 4. 判断 (2026-07-26 確定)

**判断A: 「人気(市場)」を参加者AIから除外した。** 市場人気はベースライン専用。
的中率の低下 (31.2% → 約20%) は受け入れ、市場の強さはベースラインとの差分で表す。

**判断B: 本番プリセット重みは列別(単独)学習を採用した。** 同時学習モデルは
`docs/evidence/models/20260726_preset_weights_joint425_NOT_FOR_PRODUCTION.json`
へ退避 (本番経路 `out/cache/` の外)。

**判断C: 順位規則は現行のまま。** ポイント制は不採用。
①◎的中数 → ②出し抜き数 → ③◎複勝率 → ④同点は同順位。

### 列別重みの採用条件の再確認 (`scripts_adopt_per_column.py`)

証跡: `20260726_adopt_per_column.json`

| 条件 | 結果 |
|---|---|
| 前提: 単独選択で一様分布以上 | **423/425 が一様より良い、悪い列 0** (同時学習は悪化する列あり) |
| (b) 列別有効サンプル | 閾値500未満 266/425、通過0 2列 (データ可用性の問題、方式とは無関係) |
| (c) 全セル単独選択の応答性 | 応答 **423/425**、係数潰れ **0** |
| (d) 自信度閾値 | 鉄板級≥0.4679 / 有力≥0.1822 (`normalized_gap_v1`、n=15,549) |
| 列構成指紋 | `9071c04cd52feae9` = 現行 spec と一致 |

### 実装上の注意 (判断A の効き方)

`popularity` は **基底列としては425列に残している**。除外は参加者に見える面
(選択肢・スコア・寄与・バックテスト・成績比較) のみで、単一の入口
`configs.normalize_config` が落とす。理由:

- 行列キャッシュ (4.6GB) と列構成指紋の互換性が保たれ、再構築が不要
- ベースラインの「1番人気AI」は horse の `pop` を直接使うのでこの列に依存しない
- **列別学習は列ごとに独立なので、除外しても他列の重みは変わらない** (再学習不要)

実UI (2025-07-05、36レース) での確認:

| | 判断前 (同時・人気込み) | 判断後 (列別・人気なし) |
|---|---|---|
| ◎が1番人気と一致 | 95.9% | **44%** (36レース中16) |
| 「なぜ◎か」の内訳 | 人気(市場) +100% | **平均着順 +57% / 着差 +42% / タイム指数 −1%** |
| 人気を出し抜いた的中 | 0回 | 4回 |
| 選択肢の項目数 | 29 | 28 (人気を除外) |

旧設定 (人気入り) は読み込み時に落とし、警告カードで
「『人気(市場)』は予想に使わない項目になったため、この設定から外しました」と開示する。

### 「◎が1番人気と一致 44%」の読み方 (将来この数字が動いたときの判断基準)

**44% は健全なレンジであり、低いほど良い数字ではない。**

- 95.9% → 44% の変化が意味するのは「参加者の選択が実効性を取り戻した」こと。
  ここが 90%台に戻っていたら、市場人気が再びスコアを支配している疑い。
- 一方で 44% 自体は、**人気を使わない特徴量でも市場と半分弱は同じ結論に達する**
  ことの自然な現れ。過去成績・タイム指数といった項目は市場が織り込んでいる情報と
  重複しているので、独立に評価しても一致するのが当然である。
- したがって 0% に近い値は「良い」ではなく異常。市場と系統的に逆を向いている
  (単なる逆張り) ことを意味し、的中率も崩れているはず。
- 目安: **30〜60% 程度なら正常**。ここを大きく外れたら、重みの符号や
  向き付け (`higher_is_better`)、あるいは列の取り違えを疑って調べる。

## 5. 未検証・限界

- **列別学習の既知のトレードオフ: 項目間の相関を無視するため、相関の強い項目を
  複数選ぶと同一情報が重複して効く。** 順位付けと寄与表示の用途では許容とする
  (設計書 v0.3 §5)。極端な例として425列すべてを同時に使うと -15.39 まで悪化する
  (参加者は数項目しか選ばないのでこの使い方はしない)。選択数の上限は未設定。
- 自信度ラベルは尺度不変にしたが、分布の形は設定ごとに違うため三等分には
  ならない (4項目で鉄板級5〜6%)。項目数が少ないほど差がつきにくいのは事実
  なので誤りではないが、設定ごとの閾値を持てばより正確になる。
- コーナー系2種は列別学習でも一様分布とほぼ同等 (-2.5987 vs -2.5995)。
  この件数では実質的な情報がない。
