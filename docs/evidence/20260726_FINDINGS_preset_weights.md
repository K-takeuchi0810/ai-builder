## 2. 同時学習の重みは「人気」に集中し、少数選択で尺度が壊れる

同時学習の重み上位: `popularity` **+1.2037**、2位 +0.0666 (**18倍**)、
中央値の **203倍**、全重み絶対値の **23.8%**。

表示期間 (2025-07-01以降、学習に使っていない **3,702レース**) での実測:

| 参加者の選択 | 同時学習<br>◎=1番人気 / ◎的中 | 列別学習<br>◎=1番人気 / ◎的中 |
|---|---|---|
| 人気だけ | 95.9% / 31.2% | 95.9% / 31.2% |
| 人気 + 集計3種 | 95.8% / 31.2% | **74.2% / 29.0%** |
| 人気 + 集計3種 + 騎手/近走 | 95.1% / 31.1% | **65.5% / 27.2%** |
| 人気なし・集計3種 | 9.8% / 8.1% | **39.6% / 20.3%** |
| 人気なし・タイム指数のみ | 16.1% / 12.1% | 16.1% / 12.1% |
| 人気なし・コーナー系のみ | 1.4% / 2.8% | **32.9% / 19.0%** |

### 同時学習だと「項目を選ぶ」体験が見かけだけになる

設定を変えたとき ◎ が変わるレースの割合:

| 比較 | 同時学習 | 列別学習 |
|---|---|---|
| 人気だけ → 人気+集計3種 | **0.2%** | 26.6% |
| 人気だけ → 人気+集計3種+騎手/近走 | **2.2%** | 36.1% |

同時学習では、人気を選んだ参加者が他に何を足しても ◎ はほぼ動かない
(0.2〜2.2%)。全員の予想が 1番人気AI と一致し、順位表も同着だらけになる。

### 学習期間での平均対数尤度 (高いほど良い)

| 選択 | 列別 | 同時 | 一様 |
|---|---|---|---|
| 人気だけ | **-2.0048** | -2.0099 | -2.5995 |
| タイム指数(同距離・直近3走)のみ | **-2.5793** | -2.5984 | -2.5995 |
| 平均着順(全レース・直近5走)のみ | **-2.4108** | **-2.6074** ⚠ | -2.5995 |
| 人気なし・集計3種 | **-2.4363** | -2.5959 | -2.5995 |
| 人気 + 集計3種 | -2.2352 | **-2.0096** | -2.5995 |
| コーナー系2種 | **-2.5987** | -2.5995 | -2.5995 |

⚠ 同時学習の重みは「平均着順のみ」を選ばれると **一様分布より悪い**。
425列同時のときだけ最適な重みなので、部分集合では壊れる。

逆に列別重みを425列全部に同時投入すると -15.39 と破滅的 (冗長性を補正しない
ので二重計上になる)。**参加者は数項目しか選ばないので、この使い方はしない。**

## 3. 自信度ラベルは尺度不変な差に作り直した

旧実装は「1位と2位の生のスコア差」の分位点。生の差は選んだ項目数と重みの
大きさに比例するので、425列で決めた閾値は少数選択に当てられない。
2026年600レースでの実測:

| 閾値の出どころ | 適用先 | 鉄板級 / 有力 / 混戦 |
|---|---|---|
| 同時・旧(生の差) | 425列 | 35% / 27% / 38% |
| 同時・旧(生の差) | 4項目 | 4% / 42% / 54% |
| 同時・旧(生の差) | 3項目(人気なし) | **0% / 0% / 100%** |
| 列別・旧(生の差) | 4項目 | **0% / 0% / 100%** |

`presets.normalized_gap` = (1位-2位) ÷ レース内スコアの標準偏差。
全重みを定数倍しても値が変わらないので、同じ閾値をどの項目数でも使える。

差し替え後 (`scripts_recompute_thresholds.py`、2026年800レースで確認。
証跡: `20260726_confidence_rescale.json`):

| 適用先 | 同時 (閾値 0.370/0.207) | 列別 (閾値 0.468/0.182) |
|---|---|---|
| 425項目すべて | 38% / 26% / 37% | 46% / 29% / 24% |
| 4項目 (人気+集計3) | 8% / 70% / 22% | **19% / 45% / 37%** |
| 3項目 (人気なし) | 19% / 21% / 60% | **22% / 33% / 45%** |
| 1項目 (タイム指数) | 38% / 12% / 50% | 33% / 19% / 48% |

100% 混戦は解消。**列別学習の方がどの設定でも分布が均等**で、自信度ラベルが
情報を持つ (判断B の材料をもう一つ追加)。

**古い形式の閾値は解釈を拒否する** (`scale` キーが無ければ `—` を返す)。
尺度の違う値を突き合わせて「混戦」に張り付いた自信度を見せる事故を防ぐ。

## 3.5 実UIでの確認 (2025-07-05 の実データ36レース、列別重み)

`python -m builder.api --date 20250705 --require-confirmed --weights out/cache/preset_weights_percol.json`
で実際に画面を動かした結果。同じレース (福島11R ＴＵＦ杯) で比較:

| | 人気を含むAI | 人気なしAI |
|---|---|---|
| 「なぜ◎か」の内訳 | **人気(市場) +96%**、タイム指数 +4% | **平均着順 +58%、着差 +42%** |
| ◎ | 11 エコロアゼル (1番人気) | 15 オーブルクール (3番人気、出し抜きバッジ) |
| 1番人気の扱い | ◎ | **×** |
| バックテスト ◎的中 (1,728レース) | 30% (基準33%) | 20% (基準33%) |
| 当日36レースの ◎的中 | 13 (**基準と同じ**) | 10 |
| 人気を出し抜いた的中 | **0回** | **4回** |

同時学習だと同じ設定で「人気(市場) **+100%**、タイム指数 +0%」となり、
参加者が選んだ項目が説明にまったく出てこない。

つまり **人気を選べる限り、参加者のAIは「1番人気だから」と説明する機械になる**。

## 4. 残っている製品判断 (利用者に委ねる)

技術的な対処は済んでいる。決めるべきは次の2点。

### 判断A: 「人気(市場)」を選択肢に残すか

| 選択肢 | 結果 |
|---|---|
| 残す | 選んだ参加者は ◎的中 31.2% (最良) だが、◎が1番人気と 95.9% 一致し、他の項目を足しても 0.2〜2.2% しか動かない。順位表が同着だらけになる。 |
| 外す | 全員のAIが実際に differentiate する。◎的中は 20% 前後 (1番人気ベースライン 33% を下回る)。 |

「参加者がパラメータを選んで自分好みの予想AIを作る」という製品趣旨からは
**外す**方が筋が通るが、デモで的中率が基準を下回るのを許容するかは判断が必要。

### 判断B: 本番の重みを同時学習と列別学習のどちらにするか

| | 同時学習 | 列別学習 |
|---|---|---|
| 人気を含む設定 | ◎的中 31.2% (最良) | 29.0% (-2.2pt) |
| 人気を含まない設定 | 8.1% / 2.8% (一様以下の場合あり) | 20.3% / 19.0% |
| 選択が印を動かすか | 0.2〜2.2% (ほぼ動かない) | 26.6〜36.1% |

判断A で人気を外すなら **列別学習が明確に優位**。
人気を残すなら、的中率2.2ポイントと引き換えに製品として機能させるかの判断。

いずれの場合も両方のファイルは残してある:
`out/cache/preset_weights.json` (同時) / `preset_weights_percol.json` (列別)。

## 5. 未検証・限界

- 列別学習は冗長性を補正しない。相関の高い項目を多数選ぶと二重計上になる
  (実測: 425列全部で -15.39)。選択数の上限を設けるかは未検討。
- 自信度ラベルは尺度不変にしたが、分布の形は設定ごとに違うため三等分には
  ならない (4項目で鉄板級5〜6%)。項目数が少ないほど差がつきにくいのは事実
  なので誤りではないが、設定ごとの閾値を持てばより正確になる。
- コーナー系2種は列別学習でも一様分布とほぼ同等 (-2.5987 vs -2.5995)。
  この件数では実質的な情報がない。
