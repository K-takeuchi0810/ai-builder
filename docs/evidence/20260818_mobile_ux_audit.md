# MAIBuilder スマホUX監査・改修記録（2026-08-18）

## 対象と条件

- 公開画面: `https://takeuchi-pc.taila54ab6.ts.net/`
- ビューポート: 390 × 844 px（iPhone相当）
- 確認画面: レース一覧、過去結果、レース結果、成績、マイAIの非開催日状態、共有管理
- 操作確認: 競馬場切替、レース直開き、結果URLの再読込、同日一覧への復帰、成績期間切替

## 改修前の主な課題

1. 過去36レースが1つの選択欄に入り、競馬場とレースを探しにくかった。
2. 終了レースでは変更情報・警告が着順と払戻より先に並び、最初の画面内で結果を確認できなかった。
3. 当日の購入記録が空の場合、過去成績を見るには上部の期間タブまで視線を戻す必要があった。
4. 共有管理の主要操作がスマホ幅で縦に割れ、MAIBuilderへ戻る操作とログアウトの優先度が分かりにくかった。
5. 終了レースのURLを再読込すると、履歴データより先に結果画面が描画され、競馬場・馬場・距離が一時的に欠ける場合があった。

## 実施した改修

1. 「結果を見るレース」を競馬場タブ（札幌・新潟・中京）→1R〜12Rの直接ボタンへ変更。別途「開く」を押す操作を廃止した。
2. 終了レースは着順、評価項目、払戻を先に表示し、変更・注意情報は件数付きの折りたたみに移動した。
3. 結果ヘッダーに「同日のレース一覧」を追加し、同じ開催日・競馬場選択へ戻れるようにした。
4. 当日の成績が空の場合に「前回開催の成績を見る」を追加した。
5. 共有管理の「MAIBuilderを使う」を主操作として強調し、ログアウトと横並びに整理した。
6. すべての追加ボタンを44px以上のタップ領域にし、フォーカス表示と350px以下の2列表示を追加した。
7. 結果URLの再読込時は対象開催日のレース取得を待ってから画面を描画するようにし、芝/ダート・距離・馬場状態を復元した。

## 確認上の制約

- 監査日はJRA開催日ではないため、発走前のライブオッズ、馬体重更新、買い目作成からスマッピーQRまでの画面操作は実データで再実行していない。
- 該当箇所は既存DOMテストと44pxタップ領域のコード検査で回帰を確認した。次回開催日は実オッズが入る状態で最終確認する。
- VoiceOver/TalkBackの実機読み上げまでは実施していない。競馬場タブには選択状態、レースボタンには競馬場・レース番号・名称・状態を読み上げるラベルを設定した。
